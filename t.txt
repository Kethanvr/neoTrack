# 1. Executive Summary

NeoTrace AI is a privacy-first Visual AI browser agent that monitors a user’s activity inside Google Chrome, interprets the visible browser screen using a multimodal AI model, and stores structured activity records in a database.

The product consists of:

1. A Chrome extension that detects active tabs, navigation, idle time and time spent.
2. A screenshot-processing pipeline that captures the currently visible browser tab with user consent.
3. A backend that securely receives activity events and screenshots.
4. A Visual AI service that classifies and summarizes browser activity.
5. A dashboard that shows activity timelines, categories and daily summaries.

The MVP does not monitor the user’s entire computer. A Chrome extension can monitor browser activity and capture the visible area of an active browser tab, but it does not automatically observe unrelated desktop applications. Chrome provides `captureVisibleTab()` for capturing the visible area of the active tab.

The system is intentionally designed with user consent, pause controls, blocked websites, screenshot deletion and sensitive-page detection so that it behaves as a transparent productivity agent rather than spyware.

# 2. Problem Statement

Users perform a large number of activities through their browsers, including:

* Reviewing documents
* Using finance applications
* Sending emails
* Applying for jobs
* Reading technical documentation
* Attending meetings
* Working with dashboards
* Writing content
* Managing invoices
* Using productivity tools

Traditional browser-history systems only record the URL and page title. They cannot explain what the user was actually doing.

For example, the URL may show that a user visited LinkedIn, but it does not explain whether the user was:

* Applying for a job
* Reading messages
* Editing their profile
* Searching for candidates
* Reading a company page

The proposed system uses browser events and visual understanding to convert raw browser activity into meaningful, structured information.

# 3. Proposed Solution

NeoTrace AI will observe browser activity after the user explicitly starts a tracking session.

During an active session, the system will:

1. Detect the active browser tab.
2. Record the page URL, domain and title.
3. Calculate how much time the user spends on the page.
4. Detect tab switches, navigation, idle state and browser focus.
5. Capture the visible tab at controlled intervals or important events.
6. Skip sensitive or blocked pages.
7. Send the screenshot and metadata to the backend.
8. Use a vision-capable AI model to understand the activity.
9. Save the structured result in PostgreSQL.
10. Display the activity through a dashboard.

Example AI-generated activity:

```json
{
  "category": "Software Development",
  "activity": "Reviewing a GitHub pull request",
  "summary": "The user reviewed code changes and comments in a GitHub pull request.",
  "application": "GitHub",
  "productivityLevel": "productive",
  "confidence": 0.91
}
```

# 8. System Components

## 8.1 Extension Popup

The popup is the primary user-facing control panel.

It will display:

* Tracking status
* Start tracking button
* Pause tracking button
* Current website
* Current session duration
* Number of activities recorded
* Screenshot setting
* Dashboard button
* Privacy settings
* Account connection status

Example states:

```text
Tracking Off
Tracking Active
Tracking Paused
Account Not Connected
Permission Required
Sensitive Page Blocked
Offline – Events Queued
```

## 8.2 Background Service Worker

The background service worker is responsible for:

* Listening to tab activation
* Listening to tab updates
* Detecting browser-window focus
* Detecting system idle state
* Maintaining the active activity session
* Calculating page duration
* Scheduling screenshots
* Sending activity batches
* Retrying failed requests
* Updating extension badge status

Chrome’s `idle` API can identify when the system changes between active, idle and locked states.

The `alarms` API can schedule periodic work, but alarms should be recreated or verified when the service worker starts because extension service workers are not continuously active.

## 8.3 Content Script

The content script will run only on sites where the user has granted access.

It will collect privacy-safe signals such as:

```json
{
  "scrollPercentage": 64,
  "clickCount": 7,
  "hasPasswordField": false,
  "hasPaymentField": false,
  "documentVisibility": "visible",
  "pageType": "article"
}
```

It will not collect:

* Typed text
* Passwords
* Search queries from input fields
* Form values
* Clipboard content
* Private messages
* Credit-card numbers

Chrome content scripts run in an isolated environment and communicate with the extension through message passing.

## 8.4 Tracking Engine

The tracking engine will maintain one active activity record at a time.

An activity starts when:

* The active tab changes
* A page finishes loading
* The URL changes
* The browser regains focus
* The user becomes active after being idle

An activity ends when:

* The user switches tabs
* The URL changes
* The browser loses focus
* The user becomes idle
* Tracking is paused
* The browser closes
* A session timeout occurs

## 8.5 Screenshot Controller

The MVP should not capture a screenshot every second.

Screenshots should be captured:

* After a new page becomes stable
* After a configurable interval such as 60 seconds
* When the user manually selects “Analyze now”
* When a meaningful interaction threshold is reached
* When an activity is about to end and no screenshot exists

The extension should capture only the currently visible tab.

Continuous video through `tabCapture` is unnecessary for the MVP and would significantly increase privacy, bandwidth, processing and storage problems.

## 8.6 Privacy Filter

Before capturing a screenshot, the extension checks:

* Is tracking active?
* Is screenshot analysis enabled?
* Is the domain blocked?
* Is the browser in an unsupported internal page?
* Is a password field visible?
* Is a payment field visible?
* Is the page classified as sensitive?
* Has the user granted host permission?
* Was the previous screenshot taken too recently?

If any condition is unsafe, the system stores only basic metadata or skips the activity entirely.

# 9. Chrome Permissions

Recommended Manifest V3 permissions:

```json
{
  "permissions": [
    "tabs",
    "storage",
    "idle",
    "alarms",
    "scripting"
  ],
  "optional_host_permissions": [
    "http://*/*",
    "https://*/*"
  ]
}
```

The extension should request broad host access only when the user activates visual tracking, rather than silently requesting access during installation.

Chrome supports optional permissions and optional host permissions that can be granted at runtime. Chrome recommends requesting the narrowest permissions required and using optional permissions when possible.

The `activeTab` permission gives temporary access after a direct user action. That is useful for manual “Analyze this page” functionality. Continuous cross-page tracking will require user-granted host permissions for the required sites.

## 11.8 Row Level Security

Each table must have Row Level Security enabled.

Example:

```sql
alter table activities enable row level security;

create policy "Users can read their own activities"
on activities
for select
using (auth.uid() = user_id);

create policy "Users can delete their own activities"
on activities
for delete
using (auth.uid() = user_id);
```

The Supabase service-role key must never be placed in:

* The Chrome extension
* Client-side Next.js code
* Public GitHub files
* Environment variables prefixed with `NEXT_PUBLIC_`

# 14. Tracking Algorithm

```text
When tracking starts:
    Create a tracking session
    Read the active tab
    Start a local activity
    Schedule screenshot analysis

When a tab is activated:
    End the previous activity
    Queue the previous activity for upload
    Start a new activity for the activated tab

When the URL changes:
    End the current activity
    Start a new activity

When the browser loses focus:
    End the current active duration
    Mark tracking as temporarily inactive

When the browser regains focus:
    Start or resume an activity for the active tab

When the machine becomes idle:
    End the current activity
    Do not count idle time

When the machine becomes active:
    Start a new activity

When tracking is paused:
    End the current activity
    Flush the local event queue
    Stop screenshots and event listeners
```

Important implementation rule:

```text
Never update the duration every second in the database.
```

Instead, save timestamps and calculate:

```text
duration = endedAt - startedAt
```

This reduces unnecessary network and database traffic.

# 15. Local Offline Queue

The extension must continue functioning when the network is unavailable.

Use `chrome.storage.local` for a small queue of unsent events.

Example:

```json
{
  "pendingEvents": [
    {
      "id": "local_uuid",
      "type": "ACTIVITY_COMPLETED",
      "attempts": 1,
      "nextRetryAt": 1785586000000,
      "payload": {}
    }
  ]
}
```

The Chrome Storage API is available to service workers and extension pages and is designed for extension-specific persistent state.

Retry policy:

```text
Attempt 1: immediately
Attempt 2: after 10 seconds
Attempt 3: after 30 seconds
Attempt 4: after 2 minutes
Attempt 5: after 10 minutes
```

After the final attempt, the event remains locally available until the next successful connection.

# 16. Authentication and Extension Pairing

The extension should not directly contain the user’s password.

Recommended flow:

1. User creates an account on the web dashboard.
2. User selects **Connect Chrome Extension**.
3. Dashboard generates a short-lived pairing code.
4. User enters the pairing code in the extension.
5. Extension sends the pairing code and device information to the backend.
6. Backend verifies the pairing code.
7. Backend generates a revocable device token.
8. Extension stores the device token locally.
9. Every extension request includes the device token.
10. User can revoke the device from the dashboard.

Example header:

```http
Authorization: Device device_token_here
```

The database should store only a cryptographic hash of the device token.

# 18. Privacy and Security Requirements

This project handles highly sensitive browser information. Privacy must be part of the core architecture, not an afterthought.

## 18.1 Mandatory Consent

Before tracking starts, show a clear disclosure:

```text
NeoTrace AI records browser-tab metadata such as page titles,
website domains, time spent and optional screenshots.

Screenshots may be processed by an external AI provider to classify
your activity. Passwords and form values are not intentionally collected.

You can pause tracking, block websites and delete your data at any time.
```

The user must actively select:

```text
I understand and enable tracking
```

Chrome policy requires prominent disclosure and informed consent before collecting user data. The disclosure cannot exist only inside a privacy-policy document.

## 18.2 Sensitive Website Blocking

Block by default:

* Banking sites
* Payment pages
* Password managers
* Authentication pages
* Medical portals
* Government identity portals
* Incognito windows
* Chrome internal pages

Detect page signals such as:

```html
<input type="password">
<input autocomplete="cc-number">
<input autocomplete="one-time-code">
```

When detected:

```text
Do not capture screenshot
Do not read the DOM
Store only “Sensitive page excluded,” or store nothing
```

## 18.3 Security Controls

* HTTPS for all communication
* Strict input validation
* Rate limiting
* Revocable device tokens
* Hashed device tokens
* Supabase Row Level Security
* Signed screenshot URLs
* Short screenshot retention
* API keys stored only server-side
* No service-role key in the extension
* No remotely hosted executable extension code
* Content Security Policy
* User data export and deletion
* Audit logging for device creation and revocation

Manifest V3 does not allow an extension to execute remotely hosted JavaScript; executable code must be included within the reviewed extension package.

## 18.4 Chrome Web Store Compliance

The extension has a clear single purpose:

> Help users understand and review their own browser activity through AI-generated summaries.

Chrome policies restrict browser-activity collection to data needed for a prominently disclosed user-facing feature. They also require secure handling and an accurate privacy policy.

This project should never be described as hidden monitoring.

Use terms such as:

```text
Personal activity assistant
Productivity timeline
Browser activity journal
Visual work summarizer
```

Avoid terms such as:

```text
Invisible tracker
Employee surveillance
Secret monitoring
Capture everything
```

# 26. Expected Challenges and Mitigations

## Challenge: Service Worker Suspension

Manifest V3 service workers do not remain continuously active.

**Mitigation:**

* Persist active-session state in `chrome.storage`.
* Reconstruct state when the worker starts.
* Use browser events rather than continuous loops.
* Verify required alarms at service-worker startup.

## Challenge: Duplicate Activity Events

Network retries could create duplicate database records.

**Mitigation:**

* Generate a client-side UUID.
* Add a unique database constraint.
* Make the activity API idempotent.

## Challenge: Excessive Screenshot Costs

Frequent screenshots increase AI and storage costs.

**Mitigation:**

* Capture on meaningful events.
* Add a minimum interval.
* Resize and compress images.
* Skip duplicate pages.
* Store only AI summaries by default.

## Challenge: Sensitive Information

Screenshots may contain personal information.

**Mitigation:**

* Explicit consent.
* Password-field detection.
* Payment-field detection.
* Blocklist support.
* Manual pause button.
* Temporary storage.
* Immediate deletion after processing.
* Avoid transcribing personal information in AI output.

## Challenge: AI Hallucination

The model may incorrectly classify an activity.

**Mitigation:**

* Return a confidence score.
* Use a restricted category list.
* Validate structured JSON.
* Allow users to edit categories.
* Fall back to domain-based classification.
* Show “Uncertain activity” for low-confidence results.

## Challenge: URL Privacy

URLs may contain search terms, document IDs or tokens.

**Mitigation:**

* Remove query strings by default.
* Remove fragments.
* Store domain and safe pathname.
* Never store known authentication parameters.
* Give users a metadata-only mode.

# 28. Form Answer: “What Was Your Approach?”

I approached the problem as a privacy-first full-stack browser activity system. I first designed a Manifest V3 Chrome extension to detect active-tab changes, page navigation, browser focus and idle time. The extension calculates the duration of each activity and captures the visible tab only after the user explicitly enables screenshot analysis.

Before capturing, the extension checks blocked domains and sensitive page signals such as password or payment fields. Activity metadata and temporary screenshots are sent securely to a Next.js backend. A multimodal AI model analyzes the screenshot and returns a structured category, activity name, summary, productivity level and confidence score.

The processed result is stored in PostgreSQL and displayed through a dashboard containing an activity timeline, category analytics and daily summaries. I also implemented pause controls, offline event queuing, device authentication, user-level database security and data deletion. I divided the project into feature branches and preserved the full Git and merge history rather than squashing commits.

# 31. Project Conclusion

NeoTrace AI demonstrates a complete full-stack and AI engineering workflow rather than only a frontend prototype. It combines browser APIs, event-driven tracking, offline state management, secure backend APIs, multimodal AI, structured database design, authentication, privacy controls and analytics.

The most important engineering decision is to avoid treating “track all user activity” as unlimited surveillance. The product should provide a visible, user-controlled feature with informed consent, narrow permissions and clear data controls.

For the MVP, success is not determined by capturing the maximum possible information. Success is determined by reliably converting a privacy-safe browser session into useful, structured and searchable activity context.
